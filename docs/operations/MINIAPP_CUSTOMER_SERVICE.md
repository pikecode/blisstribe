# 小程序退款客服接入

更新时间：2026-10-13。

## 当前实现

退款详情页通过微信原生 `button open-type="contact"` 打开客服会话。用户可主动发送退款咨询卡片，卡片包含退款编号、金额、状态，链接回退款详情页。详情接口继续校验订单归属，客服人员使用管理后台查询退款记录。

“复制咨询信息”提供订单号（获取失败时使用订单编号）、退款编号、申请及批准金额、状态、申请时间、原因和微信退款单号。不包含登录令牌、手机号或支付密钥。

## 运营配置

1. 登录当前小程序的微信公众平台，在客服功能中配置实际客服人员，按平台提示完成绑定和确认。
2. 客服人员使用微信提供的接待入口接收咨询，在项目管理后台核查对应订单和退款。
3. 确认实际服务时间后再补充页面文案；当前仅提示未回复时可留言，不承诺接待时间。
4. 用真机预览包确认客服会话可打开、咨询卡片可发送、复制信息正确，并完成一次客服接收验证。

本实现复用微信客服能力，不建立自有聊天系统，也不配置消息服务器或自动回复。若需要自动接待、路由或第三方客服平台，再单独设计消息服务。

## 发布与边界

运行 `pnpm build:miniapp`，微信开发者工具打开 `apps/miniapp/dist/build/mp-weixin` 后重新预览。构建不等于微信正式发布，客服人员配置和真机接待仍需完成。

客服处理咨询不会自动批准退款或修改退款结果，退款审核继续走管理后台现有流程。

## 本轮完善与验收清单

退款详情覆盖待审核、已批准、处理中、成功、拒绝、失败及关闭状态；展示申请金额和批准金额，成功时间只在成功状态展示。不承诺固定审核时间或到账时长。

进入及返回详情页会重新请求状态；支持下拉刷新和点击刷新。首次加载失败提供重试和返回入口；刷新失败保留上次信息并明确提示。客服消息卡片、复制信息及列表标签复用相同的状态文案。

以下项目尚未完成真机验收，构建成功不能替代验收：

- [ ] 登录后关闭小程序，访问令牌过期再打开，确认自动恢复。
- [ ] 断网启动及刷新失败后恢复网络，确认不因网络失败退出登录。
- [ ] 多页面并发请求续期，以及续期期间主动退出，确认不恢复已退出的会话。
- [ ] 退款各状态、批准金额不同于申请金额、缺少退款编号及网络失败的页面展示。
- [ ] 从客服或其他页面返回退款详情，以及下拉刷新，确认状态更新。
- [ ] 微信后台配置客服人员，真机发送卡片并由客服接收；复制信息内容正确。
- [ ] 上传体验版完成验收后，再提交微信审核和正式发布。

付款退款专项仍需单独确认：微信通知重试处理、用户实际到账、处理中退款自动对账。参照支付部署与验收记录；本轮页面改动不代表这些项目已完成。
