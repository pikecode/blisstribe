日期：2026-10-14。执行依据：`docs/plans/2026-10-14-service-program-phase1-implementation-plan.md`。本表验收记录范围为一期单机构、本人购买、服务项目的咨询资格、交易、预约、履约和退款。多项目维护与随访的后续发布记录见本文末尾；套餐内实物、收益结算、多机构账号权限等仍待完成，不能把一期验收视为全部产品需求完成。

## 交付内容

后台入口：服务方案、咨询线索中的购买资格、服务订单、服务预约、服务退款。患者入口：产品详情的可售方案、个人中心的我的服务、服务消息、预约与退款详情。

机构接待时间采用北京时间，可维护每周接待日及每日起止时间。时段必须处于接待时间内。申请确认期限累计四个接待小时，并受开始前一小时限制。未确认超时释放权益和名额，产生站内提醒。

免费体验按患者与方案限领。资格确认记录医生、机构方案、日期、有效期、管理员及业务依据。实际核销登记执行人员与完成操作人。医生护士无需登录。

改约建议不占名额，患者接受时复核容量、时间冲突、权益资格和有效期。机构取消原时段后明确显示取消，患者接受替代时段时重新占用一次权益。未到场释放次数并暂停项目预约，恢复须填写说明。

机构等待区间合并计算，不足一天按一天、重叠不重复延期。延期记录与原因展示给患者。到期未使用数量停止预约，仍可作为客服和退款处理依据。

退款审核与渠道结果分开。未知或异常结果保持冻结；只有微信明确确认成功才结转权益与退款金额。微信确认 CLOSED 且退款单号和金额一致时，管理员可释放冻结并由患者重新申请。ABNORMAL 保持查单与人工核查，不能手工改成成功。

## 上线配置与真机放行

1. 在后台选择已审核主体建立履约机构，确认地址、接待日和时间。
2. 配置服务方案、价格和规则，先开放未来时段，再上架。
3. 对需评估方案登记确认医生和业务资格，不登记病历或诊断。
4. 使用微信开发者工具打开 `apps/miniapp/dist/build/mp-weixin`，真机预览检查方案、协议确认、预约、取消、消息、客服、退款详情及返回刷新。
5. 使用获授权的测试患者完成小额真实支付。核对微信交易号、本地实付金额、一次权益发放和支付回调；拒付或取消不会生成服务权益。
6. 批准测试退款，核对微信退款 SUCCESS、本地冻结释放与退款数量、原支付账单到账记录。回调地址为 `https://api.ytxybl.com/api/v1/service-program/webhooks/wechat-pay` 和 `.../wechat-refund`。
7. 按实际验收记录决定向真实患者开放方案。不能用模拟渠道结果作为真实到账证明。

当前后台账号为平台管理账号，拥有全平台权限。首期不得给其他机构人员分发平台管理凭证；多机构隔离账号尚属后续阶段。微信订阅消息推送未启用，通知通过站内消息与机构运营协调完成。

## 套餐实物发布与运营

1. 服务方案增加“套餐实物”，选择商城已上架规格、数量、交付方式，填写分摊金额及退货条件／期限／运费承担。服务套餐至少保留一个服务项目。
2. 购买后在服务订单详情查看交付，现场商品备妥后登记可领取；寄送商品先由患者选择本人地址，再登记已寄送快递。运营代确认必须有交付依据。
3. 已寄送但需取消：先确认快递拦截成功且实物已取回，凭依据撤回寄送，再由患者申请未交付退款，不能仅取消单号便释放库存。
4. 患者收到商品后可在我的服务申请退货、填写原因及照片。个人原因默认交付后 7 天；质量、错发、缺损问题保留受理入口。
5. 运营批准时填写退回地址与联系人、运费处理说明，寄回期限为 7 天。未寄回前可凭沟通更新地址及延期；目前逾期提醒、受理与核验工作时限由运营人工跟进，不会自动关闭申请。
6. 收到后核验数量、状态及问题。符合条件时明确是否可重新销售，再生成服务退款供财务审核；不符时登记核验异议并继续沟通，不直接丢弃商品。
7. 微信确认退款后终结对应商品权益，检验可重售的商品才恢复库存。零元赠品不补价、不重算其他项目价格，不发起微信零元资金退款。

本次未执行业务自动化测试、库存并发验证、微信真机和真实支付退款验收。正式使用前需覆盖库存抢占、超时关单、部分商品退款、领取／寄送、照片上传、退货核验可重售／不可重售、退款异常和零元赠品。小程序仍需真机预览与上传发布。特殊商品政策配置、另购商品关联计划、成本与收益结算仍待后续实施。

## 已完成服务异议发布与运营

版本 `20261014-service-disputes-01`，追加迁移 019，生产累计 48 个迁移；备份 `/opt/blisstribe/backups/20261014-service-disputes-01`，前一版本 `20261014-service-goods-01`。三端生产构建与小程序类型检查通过。发布后 API active、后台异议页面及公开方案 HTTP 200、未登录管理和患者异议接口 HTTP 401，error 级日志检查无记录；本次未运行新增业务自动化测试、不同账号联调或真实微信例外退费。

后台入口：`https://admin.ytxybl.com/service-disputes`。患者从已完成预约进入“反馈记录问题”，已有异议直接进入原详情；“我的服务”也可查看相关异议列表。

1. 客服受理时登记实际联系情况和负责人，默认首次联系期限 1 个工作日；随后机构依据期限 2 个工作日，登记业务执行依据，不填写诊疗资料。
2. 收到依据后默认 2 个工作日提出方案。原服务登记人不能自行提出终结方案。方案包括维持记录、恢复一次、纠正实际项目、重新安排及例外退费。
3. 患者接受维持／恢复／纠正方案后执行并结案；恢复次数涉及已过期计划时，必须明确新的有效期。原记录不删除，修正原因和次数变动保留。
4. 重新安排恢复权益后继续开放，患者重新预约；运营关联同一项目、患者接受后新建且已确认（或已到场／完成）的预约，再结案。不能用同一个新预约关闭多个异议。
5. 患者不接受首次方案进入 3 个工作日独立复核，复核人需与原登记人和原方案提出人不同。不接受复核结果继续争议协调，不因沉默或管理员已回复就结案。
6. 例外退费明确金额、承担方、机构／主理人冲回口径。患者接受后生成服务退款，原登记人、方案提出人和复核人不能审批该资金退款，需由其他管理账号审核。微信成功才结案；失败时继续协调、重新生成申请或调整方案再取得患者接受。
7. 到期前需延长反馈期限时，登记原因和下一次反馈时间。后台“仅看处理超期”用于跟进，系统每 15 分钟发送一次对应期限的超期站内提醒，不自动结案。

支持日历配置为 `SERVICE_SUPPORT_NON_WORKING_DATES`（节假日）和 `SERVICE_SUPPORT_WORKING_DATES`（调休工作日），逗号分隔北京时间 `YYYY-MM-DD`。未配置时按周一至周五计算；正式运营前需核对日历。需准备不同的管理账号完成原记录、方案处理、复核与资金审核；当前仍是平台全局管理权限，不能据此向多机构开放隔离账号。

结算暂停字段和冲回说明目前为业务记录，机构／主理人财务账本及实际冻结尚未建设。本次不覆盖执行中异常、机构主动撤销错误登记和完整医护人员记录。回滚到旧版本后不要使用旧后台处理新异议补偿申请，渠道通知后的工单进度须由支持异议的新版本继续核对。
