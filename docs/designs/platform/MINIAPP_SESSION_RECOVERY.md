# 小程序登录态恢复

更新时间：2026-10-13。

## 方案与边界

采用短期访问令牌和刷新令牌自动续期，沿用现有后端接口；不延长访问令牌有效期。默认访问令牌为两小时、刷新令牌为七天，最终以服务端配置为准。长期未使用、会话被撤销、主动退出或本地缓存被清理后需要重新登录。

## 执行流程

1. 启动、回到前台时恢复缓存；访问令牌过期但刷新令牌有效时调用 `/auth/refresh-token`。
2. 登录显示允许存在刷新令牌的会话继续恢复；这只用于客户端展示，服务端仍逐次校验访问权限。
3. 普通请求、启动恢复和头像上传共用刷新中的 Promise，避免同时兑换同一个刷新令牌。
4. 普通请求遇到令牌过期，或携带令牌却收到未登录错误时，续期后最多重试一次。旧请求迟到时使用已经刷新的令牌重试。
5. 刷新成功后存储新令牌，访问令牌缓存有效期使用服务端返回的 `expiresIn`。
6. 明确的认证失败清除令牌和用户缓存；网络错误、服务器错误保留会话，后续操作可重试。
7. 用户退出或切换登录后，旧会话的刷新响应不能恢复已退出的登录。

## 工程原则

- KISS、DRY：集中在现有请求模块处理续期，页面与上传复用。
- SOLID：存储负责缓存有效期，请求模块负责会话恢复，服务端负责身份校验。
- YAGNI：不增加后台定时刷新、永久令牌或新的认证依赖。

## 验收范围

需要用真机确认：超过两小时重新打开、断网后恢复、并发加载、刷新令牌失效、主动退出时正在刷新、头像上传。构建成功不等于以上场景已完成验收。
