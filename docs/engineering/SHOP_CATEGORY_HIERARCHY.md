# 商城两级分类

## 分类规则

- 一级分类：`parentId = null`；二级分类：`parentId = 一级分类 ID`。
- 最多两级，禁止选择自身、形成循环，或把有子分类的一级分类直接改为二级。
- 二级分类可调整到其他一级分类，也可提升为一级分类。
- 商品可继续挂在一级分类，也可挂在二级分类，不强制修改历史商品。
- 选择一级分类查询商品时，包含直接关联商品和所有二级分类下的商品；选择二级分类只查该分类商品。
- 停用一级分类后，其二级分类和相关商品对用户隐藏；恢复一级后，原本启用的子分类恢复显示。停用子分类不影响同级其他分类。
- 分类停用也影响新加入购物车和新下单。历史购物车中的相关商品显示不可购买，历史订单记录保留。

## 后台维护

“商城经营 → 商品分类”按树形展示。一级分类操作区提供“新增二级分类”；新增或编辑弹窗中也可选择“上级分类”，留空为一级。

商品列表筛选和新增、编辑表单中的分类以“一级 / 二级”路径显示，支持直接关联到一级。

## 小程序交互

- 商城首页：左侧一级分类，右侧二级分类筛选与双列商品卡片。
- 一级分类下默认选择“全部”，包含该一级分类本身的商品。
- 搜索页保留两行分类筛选：一级分类与当前一级下的二级分类。
- 切换一级时重置二级，重置分页；仅请求成功后前进页码。
- 快速切换分类时忽略过期请求返回，避免商品串入其他分类。
- 无子分类时隐藏二级筛选；无商品时可返回查看全部。

## 接口

分类接口继续返回扁平数组，新增可空字段 `parentId`，兼容已有调用方。管理端新增、编辑分类传数字 `parentId`；传 `null` 表示一级，编辑时省略表示保持原归属。

```json
[
  { "id": 1, "name": "生活好物", "parentId": null },
  { "id": 2, "name": "杯具", "parentId": 1 }
]
```

## 数据迁移与发布顺序

迁移：`20261020000100_add_shop_subcategories`。只增加可空字段、外键、索引、自引用检查与层级校验触发器，历史分类自动保持为一级。触发器通过事务锁协调并发分类归属调整。

发布时先备份数据库，再执行迁移、生成 Prisma Client 并构建 API，随后更新后台和小程序。新 API 必须在迁移完成后启动。代码回滚可保留新增结构，旧代码仍可使用原字段；分类已经分级后的旧版商城界面会以平铺形式显示分类。

迁移已于 2026-10-20 在线上执行，API 与后台已发布。完整备份及回滚信息见[二级分类发布记录](../operations/deployments/2026-10-20-shop-categories-01.md)。小程序正式版仍需要通过微信开发者工具上传和发布。

## 核对范围

- 分类服务：一级停用、二级创建、禁止三级/自引用/带子分类降级、移动与提升一级。
- 购物车和下单：停用父分类后不能继续购买，不能增加库存占用。
- 数据库：保留历史分类；允许合法二级、移动、提升；阻止三级、循环与自引用。
- 三端类型检查、商城单元测试、小程序编译。
