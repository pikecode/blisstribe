# 服务方案交互原型

日期：2026-10-14。需求依据：[服务方案销售与履约需求确认文档 V1.2](../../product/SERVICE_PROGRAM_REQUIREMENTS.md)。

本原型用于评审患者端和机构运营端的页面及交互，不代表正式业务功能已开发。

## 打开方式

在仓库根目录执行：

```bash
python3 -m http.server 4178 --bind 127.0.0.1 --directory docs/prototypes/service-program
```

浏览器访问 **http://127.0.0.1:4178**。使用完成后在终端按 Ctrl+C 停止。

也可以直接打开 `index.html`，但本地文件模式的浏览器存储行为可能不同；推荐以上启动方式。不需要安装依赖。

## 建议评审路径

1. 患者端提交咨询，领取免费体验并提交预约。
2. 切换机构运营，在“预约与执行”确认预约、确认到场和登记完成。
3. 在“咨询与评估”登记允许购买的方案。
4. 切回患者端，购买阶段方案、勾选规则并模拟付款，然后预约具体服务。
5. 运营确认和完成后，切回患者端查看剩余次数和实际服务记录。
6. 载入“已完成三次服务”场景，患者申请退剩余七次，金额应为 630 元。
7. 运营批准退款后，患者看到渠道处理中；运营模拟渠道成功后，已退次数终结。
8. 尝试部分退款、撤回申请、拒绝退款、退款异常、取消预约和已领取商品。

侧栏的场景按钮会替换本浏览器中的演示记录。右侧“页面状态”提供加载中与加载失败；点击重试可以恢复。

## 本轮可评审

- 服务介绍、免费体验、收费评估、单次与多次服务方案。
- 机构评估资格对购买入口的影响。
- 购买确认、模拟支付、我的服务、服务计划详情。
- 预约申请、机构确认、到场、完成和一次核销。
- 实际医生护士与运营登记人分别展示。
- 套餐商品现场领取。
- 未使用次数与未领取商品的退款选择、预约一并取消、冻结与解除冻结。
- 审核通过与渠道退款成功分开显示；异常退款保持冻结。
- 演示订单的主理人收益、机构应结算及观察期说明。
- 两个角色共享记录，刷新浏览器后保留演示业务进度。

## 演示边界

- 所有患者、人员、时间和业务内容为演示数据，支付和渠道结果由按钮模拟。
- 不连接 API、微信支付或客服，不发送消息，不影响真实库存和资金。
- 当前只使用一个机构和一位虚构患者。不要输入真实医疗资料或个人联系方式。
- 不模拟真实时间流逝：30 天来源、90 天方案有效期、预约超时与 7 天观察期仅呈现规则，不自动到期或结算。
- 候选时间以打开当日为基准，演示购买资格固定对应两个服务方案。
- 客服和改约入口展示说明；改约通过取消旧预约后重选实现，不演示机构反向提议时间。
- 服务异议提供患者提交流程和冻结提示，暂不包含完整复核与结案流程。
- 套餐物流退货、方案替换、资格暂停、多机构、独立主理人工作台和完整财务结算属于后续原型范围。
- 本次不提供发布或上传微信入口。原型存储与业务应用存储独立；重置演示只清除本原型记录。

## 文件

- `index.html`：入口。
- `styles.css`：患者手机预览、运营工作台和响应式样式。
- `app.js`：演示状态与交互。

采用普通浏览器页面和本地演示记录，方便评审和迭代；正式开发仍以已确认需求为准。

## 本轮检查记录

2026-10-14 使用浏览器实际点击检查：

- 方案购买 → 提交预约 → 机构确认 → 到场 → 完成；完成一次后已使用次数为 1。
- 免费咨询 → 免费体验预约 → 机构完成体验 → 登记允许购买；不产生付费订单。
- 完成三次服务后申请退剩余七次，金额为 630 元。
- 审核通过后仍为渠道处理中；模拟异常后继续冻结；模拟成功后保存成功结果。
- 已预约时选择退两次，金额为 180 元，预约同步取消；撤回退款不会恢复原预约。
- 无档期场景不提供购买入口；加载失败后重试恢复页面。
- 浏览器刷新保留演示退款记录；390 像素窄屏无页面横向溢出。

以上只验证原型交互，不代表真实支付、微信小程序或服务端业务验收。
